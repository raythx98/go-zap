# Architecture

## Overview

go-zap is a REST API server for URL shortening with analytics. It is the backend for the Zap React frontend. It handles user auth (JWT), URL CRUD, and redirect tracking (device, country, city). Built in Go using a layered architecture with SQLC for type-safe database access.

## Layer Structure

```
┌─────────────────────────────────────────────────────────────────┐
│  HTTP Server  (cmd/api/main.go)                                  │
│  Routes registered in endpoints/endpoints.go                    │
│  Middleware: CORS · rate limit · request ID · logging           │
├─────────────────────────────────────────────────────────────────┤
│  Controller Layer  (controller/)                                 │
│  Unmarshal request · call service · write response              │
├─────────────────────────────────────────────────────────────────┤
│  Service Layer  (service/)                                       │
│  Business logic · orchestrates repository calls                 │
├─────────────────────────────────────────────────────────────────┤
│  Repository Layer  (repositories/)                               │
│  Data access via SQLC-generated functions                       │
├─────────────────────────────────────────────────────────────────┤
│  Infrastructure  (tools/)                                        │
│  config · postgres · crypto · zerologger · mw_helper           │
└─────────────────────────────────────────────────────────────────┘
```

## Request Data Flow

```
HTTP Request
  │
  ├── Router (endpoints/endpoints.go)
  │     └── Middleware chain (per-endpoint)
  │           ├── Request ID injection
  │           ├── Rate limiting (token bucket, per YAML)
  │           ├── Auth (JWT or Basic Auth, per endpoint)
  │           └── Logging (zerolog)
  │
  ├── Controller
  │     ├── Unmarshal + validate request body
  │     ├── Call service method
  │     └── Write JSON response
  │
  ├── Service
  │     ├── Business logic
  │     └── Call repository methods
  │
  └── Repository
        └── Execute SQLC-generated query
```

## Dependency Wiring

`resources/resources.go` is the composition root. It wires:
- `Tools` — Logger, Postgres, JWT, Crypto
- `Repositories` — DB query functions wrapped in interfaces
- `Services` — business logic, injected with repositories
- `Controllers` — HTTP handlers, injected with services
- `Endpoints` — route registration, injected with controllers + middleware helpers

## Authentication

Two auth mechanisms are used:
1. **JWT Bearer** (`Authorization: Bearer <token>`) — for user-specific operations (dashboard, link management).
2. **HTTP Basic Auth** — for registration, login, and redirect tracking (prevents anonymous access).

The middleware templates in `gohelpme/middleware` handle both. Routes in `endpoints/endpoints.go` declare which middleware applies.

## URL Shortening

- Short URLs are 10-character alphanumeric strings generated by `tools/random/`.
- Uniqueness is enforced by a partial unique index on `(short_url)` where `is_deleted = false`.
- Soft deletes: deleted links set `is_deleted = true`, freeing the short URL for reuse (the unique index allows re-creation).

## Analytics

Redirect tracking stores:
- `device` — parsed from User-Agent by the Zap frontend (using `ua-parser-js`) and passed in the request body.
- `country` / `city` — resolved from the client IP by the backend (or passed by the frontend via an external geolocation API).

## API Documentation

Swagger docs are auto-generated by `swag` from annotations in `controller/` and `dto/`. Served at `/swagger/`.

## Code Generation

| Tool | Input | Output |
|------|-------|--------|
| `sqlc` | `sqlc/query.sql` | `sqlc/db/` |
| `swag` | Controller + DTO annotations | `docs/` |
| `mockery` | Interface definitions | `mocks/` |

**Never manually edit `sqlc/db/`, `docs/docs.go`, `docs/swagger.json`, `docs/swagger.yaml`.**
